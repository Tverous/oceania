# Oceania 實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立 Oceania。兩位工程師的 agent 透過 hook 共用 Memory。master agent 追蹤每個衝突的生命週期，並依照影響決定由誰解決。spec 作者在 Slack 決定影響大的衝突。

**Architecture:** Oceania 伺服器是一個 Node process。Oceania 伺服器用 `node:sqlite` 保存 Memory，並用 `node:http` 接收 adapter 的請求。每個 agent 的 hook 執行 `oceania hook`。筆電 B 透過 `tailscale serve` 連到筆電 A 上的 Oceania 伺服器。master agent 用 Claude Agent SDK 執行判斷回合，並透過 Slack 與 GitHub 採取動作。

**Tech Stack:** Node 26.13、`node:sqlite`、`node:http`、`node:https`、`node:test`、`@anthropic-ai/claude-agent-sdk/core`、`@slack/bolt`、`zod` 4、`gh`、`git`、Tailscale。

**Spec:** `docs/superpowers/specs/2026-11-10-multiplayer-agents-design.md`

## Global Constraints

- 18:30 之前，任何人都不得在 Oceania repo 或 demo repo 建立 commit。
- P0 的實作時間是 18:30 到 21:30。P1 只在 P0 提早完成時實作。
- 這份計畫不包含產品程式碼。計畫只定義檔案、介面、測試與指令。
- 只使用可抹除的 TypeScript 語法。不使用 `enum`、`namespace` 與 parameter property。
- import 路徑必須寫出 `.ts`。只匯入型別時，必須使用 `import type`。
- 啟動指令是 `npm start`，也就是 `node --env-file=.env src/cli.ts serve`。
- 測試指令是 `npm test`，也就是 `node --test "test/*.test.ts"`。
- 型別檢查指令是 `npm run check`，也就是 `tsc --noEmit`。
- 依賴只有 `@anthropic-ai/claude-agent-sdk`、`@slack/bolt` 與 `zod`。npm 自動安裝 Agent SDK 的 peer dependency，例如 `@modelcontextprotocol/sdk`。開發用的依賴只有 `typescript` 與 `@types/node`。
- Oceania 伺服器只監聽 `127.0.0.1:4100`，因為 MVP 沒有身分驗證。筆電 B 透過筆電 A 的 `tailscale serve` 連線。筆電 A 的 tailnet 網址是 `https://wonderland.tail757928.ts.net`。
- adapter 讀取 `OCEANIA_URL`。預設值是 `http://127.0.0.1:4100`。
- 身分只來自 `OCEANIA_MEMBER`。這個值是成員的 email。
- `.env` 只有四個值：`ANTHROPIC_API_KEY`、`SLACK_BOT_TOKEN`、`SLACK_APP_TOKEN` 與 `OCEANIA_REPO=Tverous/acme-pricing`。
- `.env`、`members.json`、`oceania.db*` 與 `node_modules/` 不納入版本控制。
- adapter 遇到任何錯誤時，不輸出任何內容，並回傳 exit code 0（spec §7.2）。
- adapter 用 `node:http` 或 `node:https` 的 `request` 傳送請求，不使用 `fetch`。`OCEANIA_URL` 使用 `https://` 時，adapter 使用 `node:https`。Node 的 `fetch` 預設在 300 秒後逾時，`Stop` 最多需要等待 570 秒。
- `src/cli.ts` 只靜態匯入 `node:util`。每個子指令用 `await import()` 載入自己的模組。`oceania hook` 只載入 Node 內建的模組，因此筆電 B 不需要 `npm install`。
- 每個 task 的 Commit step 之後，執行 `git push`。筆電 B 用 `git pull` 取得最新的 `oceania hook`。
- demo 只使用英文（spec §5）。
- 送給 agent 的文字最多 9,000 個 UTF-8 位元組。這個上限是 `MAX_TEXT`。Claude Code 的上限是 10,000 字元，Copilot 的上限是 10 KB。
- 設定檔中的 node 使用絕對路徑。筆電 A 的路徑是 `/opt/homebrew/bin/node`，這是 `command -v node` 的結果。筆電 B 使用筆電 B 上 `command -v node` 的結果。
- spec §7.4 到 §7.6 的英文模板必須逐字使用。新的英文文字遵守 ASD-STE100 Strict。
- master agent 從 `@anthropic-ai/claude-agent-sdk/core` 匯入。`/core` 使用專案安裝的 `zod`。root 入口內含自己的依賴。
- master agent 的 `query()` 選項：`model: 'opus'`、`tools: []`、`settingSources: []`、`permissionMode: 'dontAsk'`、`persistSession: false`、`maxTurns: 12`。
- `allowedTools` 只列出 Oceania 的工具。`settingSources: []` 讓判斷回合不讀取任何設定檔。
- 時間常數：`SETTLE_MS = 90_000`、`HOLD_MS = 480_000`、`DEBOUNCE_MS = 1_500`、`BOARD_DEBOUNCE_MS = 1_000`、`ROUND_MS = 120_000`、`GH_TIMEOUT_MS = 30_000`、`RESYNC_MS = 60_000`、`STALL_MS = 600_000`、`TEST_TIMEOUT_MS = 60_000`。
- 所有時間都存成 epoch 毫秒（`Date.now()`）。
- adapter 的 HTTP timeout：`Stop` 是 595 秒，其他事件是 10 秒。
- 階段在程式碼中的值是 `before`、`during` 與 `after`，分別代表 spec 的發生前、發生中與發生後。影響的值是 `low` 與 `high`。
- 階段的英文標籤：`before` 是 `Before: tasks conflict`，`during` 是 `During: changes not on main`，`after` 是 `After: changes on main`。

## Review Focus

1. **Oceania 伺服器沒有啟動，或沒有設定 `OCEANIA_MEMBER`：** agent 必須照常工作。adapter 不輸出任何內容，並回傳 exit code 0。Task 3 的 `runHook stays silent when Oceania is down` 驗證這一點。
2. **Oceania 在 agent 執行期間重新啟動：** Oceania 沒有收到 `SessionStart`。之後的任何事件都必須註冊這個 session，而且第一次回報的 main 不算推送。Task 3 的 `PostToolUse registers an unknown session` 驗證這一點。
3. **兩台筆電的路徑與 origin 不同：** Claude Code 傳送絕對路徑，其他工具可能傳送相對路徑。兩台筆電的 origin 可能是 HTTPS 或 SSH 格式。檢查必須用 repo 相對路徑與正規化的 repo 比對。Task 3 的 `PreToolUse normalizes paths` 與 `normalizeRepo matches https and ssh origins` 驗證這一點。
4. **pull 與推送：** agent 執行 `git pull --rebase` 時，clone 的 main 改變，但這個 session 的檔案留在 diff 中。Oceania 不得把 pull 記錄成推送。Task 2 的 `observe ignores a pull` 驗證這一點。
5. **錯誤的人點選，或重複點選：** 只有 spec 作者能決定。已決定的衝突不能再次決定。Task 6 的兩個 `decide` 測試驗證這一點。

## 共用型別（`src/types.ts`）

Task 2 建立這些型別。之後的 task 都使用這些名稱。

- `AgentKind = 'copilot' | 'claude'`
- `Status = 'working' | 'idle' | 'paused'`
- `Stage = 'before' | 'during' | 'after'`
- `Impact = 'low' | 'high'`
- `STAGE_LABELS: Record<Stage, string>`：這是 `types.ts` 中唯一的常數。值見 Global Constraints。Memory 的事件文字、`text.ts` 與 `board.ts` 都使用這個常數。
- `EventKind = 'join' | 'task' | 'diff' | 'push' | 'conflict' | 'decision' | 'stall'`
- `Member { email, name, github?, slackId? }`
- `Session { id, agent, member, repo?, root?, base?, main?, status, issue?, cursor, updated }`
- `Task { id, session, summary, issue?, at }`
- `Diff { session, version, files: string[], patch }`
- `Note { id, session, text, blocking, delivered }`
- `Conflict { id, sessions: string[], files: string[], summary, stage: Stage, impact: Impact, status: 'open' | 'resolved', issue?, channel?, author?, question?, options?: string[], decision?, updated }`
- `Decision { issue, option, author, at }`
- `Push { session, files: string[], patch, main, at }`
- `Post { text, at }`
- `OceaniaEvent { id, kind, session?, text, at }`
- `SessionView = Session & { name, task?: Task, files: string[] }`
- `Snapshot { members, sessions: SessionView[], conflicts: Conflict[], decisions, main? }`
- `GitInfo { root, repo, base, main, files: string[], patch }`
- `HookDecision { context?, deny?, block? }`
- `Spec { issue, title, body, author, decisions: string[] }`

- `Conflict.id` 是整數。`Conflict.channel` 只在影響大的衝突交給 spec 作者後才有值。`Conflict.author` 是 spec 作者的 GitHub 帳號。
- `Session.agent` 是顯示名稱，例如 `Copilot CLI` 或 `Claude Code`。`Session.updated` 是這個 session 最後一次寫入的時間。
- `Session.repo` 是正規化的 repo，例如 `github.com/tverous/acme-pricing`。`Session.root` 是本機的 repo 根目錄。
- `Session.base` 是基準 commit，也就是 `HEAD` 與 `origin/HEAD` 的 merge base。diff 是 working tree 相對於基準 commit 的變更。因此 diff 包含已 commit 但還沒推送的變更。
- `Session.main` 是這個 session 上一次回報的 `refs/remotes/origin/HEAD`。推送的偵測使用這個值。
- `OceaniaEvent.at` 是 Oceania 加入這個事件的時間。停滯的偵測使用這個值。

`handleHook` 的規則（spec §7.2 與 §7.4）：

| 事件 | 規則 |
|---|---|
| 所有事件 | 先呼叫 `register`。`agent` 是 `AGENT_NAMES[agent]`。有 `git` 時，加入 `repo`、`root`、`base` 與 `main`。因此 Oceania 在 agent 執行期間重新啟動時，Oceania 仍然註冊 session。 |
| `SessionStart` | 回傳 `{ context: teamStatus(...) }`。 |
| `UserPromptSubmit` | session 沒有暫停時，`setStatus('working')`。`addTask` 寫入任務。`issue` 來自 prompt 中的第一個 `#N`。回傳 `{}`。 |
| `UserPromptSubmit`（續） | prompt 等於 Oceania 上一次對這個 session 回傳的 `block` 時，不寫入任務。Copilot 把 `Stop` 的 `reason` 當成新的 prompt 送出，Claude Code 不會（Task 1 的 probe）。 |
| `PreToolUse` | 第一，`pausedBy` 有值時，回傳 `{ deny: paused(...) }`。第二，有阻擋通知時，回傳 `{ deny: pending(通知).text }`。 |
| `PreToolUse`（續） | 第三，寫入工具碰到另一個 session 的 diff，而且這個 session 沒看過這個 diff 版本。這時呼叫 `markSeen` 與 `trackOverlap`，再回傳 `{ deny: overlap(...) }`。其他情況回傳 `{}`。 |
| `PreToolUse`（續） | 第三步略過同一位成員在同一個 `root` 的 session，例如重新啟動前的舊 session。第三步也略過這個 session 自己的 diff 已經有的路徑，因為先修改檔案的 session 有優先權（spec §7.4）。 |
| `PostToolUse` | 有 `git` 時，呼叫 `observe`，再呼叫 `opts.observed`。回傳 `{ context: updates(readEvents, 不阻擋的通知).text }`。沒有內容時，回傳 `{}`。 |
| `Stop` | session 沒有暫停時，`setStatus('idle')`。然後等待 `settled()`。 |
| `Stop`（續） | session 暫停時，等待 session 恢復，最多 `holdMs`。逾時時，回傳 `{}`。 |
| `Stop`（續） | `signal` 在等待期間中止時，回傳 `{}`。通知留給下一次 `Stop` 或 `PreToolUse`。 |
| `Stop`（續） | 有未送達的通知時，`setStatus('working')`，並回傳 `{ block: pending(通知).text }`。決定排在最前面，然後是阻擋通知，最後是不阻擋的通知。agent 會繼續工作。其他情況回傳 `{}`。 |

即時檢查只比較 `repo` 相同的 session。路徑先轉換成相對於 `session.root` 的路徑。repo 以外的路徑回傳 `{}`。

`hookOutput` 的格式（spec §7.2）：

`escalate` 依序執行以下步驟：
  1. 讀取衝突。衝突不存在、沒有 `issue`，或已經有 `channel` 時，丟出錯誤。
  2. 呼叫 `specs.get(issue)`，取得 spec 作者。spec 作者不在成員資料中，或沒有 `slackId` 時，丟出錯誤。
  3. `channel` 是 `oceania-<issue>-<Date.now().toString(36)>`。
  4. 呼叫 `await chat.openConflict({ ...conflict, channel, author, question, options })`。
  5. 呼叫 `memory.escalate(id, { channel, author, question, options })`。Oceania 先建立 Slack 頻道，再暫停 session。Slack 失敗時，沒有 session 暫停。
  6. 回傳 `Opened #<channel>`。

`startMaster` 的規則：
  - master agent 從啟動時的 `lastEventId()` 開始讀取事件。因此 Oceania 重新啟動後，master agent 不重新判斷舊的事件。
  - 只有 `task`、`diff` 與 `push` 事件觸發判斷回合。Oceania 與 master agent 自己的事件不觸發判斷回合。
  - Memory 變動後，等待 `debounceMs`。同一時間最多只有一個判斷回合。
  - `roundPrompt` 列出上一個判斷回合之後的所有事件，包含不觸發判斷回合的事件。
  - 判斷回合結束後，如果有新的觸發事件，再執行一次。
  - `settled()` 在兩個條件都成立時完成：沒有判斷回合執行中，而且沒有未處理的觸發事件。`settled()` 最多等待 `SETTLE_MS`。
  - 判斷回合丟出錯誤時，記錄錯誤，再處理下一批事件。
  - 每個判斷回合最多執行 `roundMs`。逾時時，`startMaster` 中止傳給 judge 的 `signal`，並記錄錯誤。
  - 逾時後，`startMaster` 不等待 judge 結束，直接處理下一批事件。因此卡住的工具呼叫不會擋住之後的判斷回合。

`claudeJudge`：
  - `signal` 中止時，`claudeJudge` 中止 `query()`。`query()` 的 `abortController` 選項接收這個中止。
  - 呼叫 `createSdkMcpServer({ name: 'oceania', version: '0.1.0', tools, alwaysLoad: true })`。
  - 每個工具都用 `tool(name, description, schema, handler)` 包裝。handler 回傳 `{ content: [{ type: 'text', text }] }`。
  - 工具丟出錯誤時，handler 回傳 `isError: true` 與錯誤訊息。因此模型知道動作失敗。
  - 呼叫 `query({ prompt, options })`。`options` 見 Global Constraints。另外，`systemPrompt` 是 `SYSTEM_PROMPT`，`mcpServers` 是 `{ oceania: server }`。
  - `allowedTools` 的值是每個工具名稱加上前綴 `mcp__oceania__`。
  - 記錄 `system` 的 `init` 訊息中的 `model`，以及 `result` 訊息。

`SYSTEM_PROMPT` 必須包含以下規則。英文措辭由實作者決定，並遵守 ASD-STE100 Strict。
  1. master agent 協調不同成員的 AI agent。
  2. 先呼叫 `read_memory`。session 有連結的 issue 時，再呼叫 `get_spec`。
  3. 對每個新事件與每個未解決的衝突，判斷階段與影響（spec §7.4）。用 `track_conflict` 建立或更新衝突紀錄。
  4. 衝突的變更不再互相衝突時，用 `track_conflict` 把衝突標記為 `resolved`。例如 main 已經有較晚的 session 配合後的工作。
  5. 影響小：用 `notify` 通知需要調整的 session（spec §7.5），再用 `post_activity` 貼出一則摘要。
     - 發生後：用 `notify` 通知還沒推送的 session。這個 session 推送前，必須先用 rebase pull main。
  6. 重複工作：兩個任務做相同的工作，或一個任務需要另一個 session 加入的資料。這是發生前、影響小的衝突。
     - 影響大的衝突未解決時，也記錄這個衝突。衝突的檔案是先開始的 session 的檔案。
     - 用 `notify` 通知較晚的 session。通知逐字使用 spec §7.5 的重複工作範例。然後貼出一則摘要。

  12. 不需要任何動作時，直接結束。

### Task 9：`check_merge`

- Oceania 伺服器在 `.oceania/repo` 保存 demo repo 的 bare clone。`.oceania/` 不納入版本控制。
- Oceania 第一次寫入 shadow ref 時，clone 這個 session 的 repo。其他 repo 的 session 沒有 shadow ref。
- 每次 `observe` 之後，`observed` 呼叫 `shadow.update`。clone 沒有 session 的 `base` 時，`update` 先執行 `fetch`。然後 Oceania 用暫存 index 執行 `read-tree <base>`、`apply --cached`、`write-tree` 與 `commit-tree -p <base>`，再更新 `refs/oceania/<session>`。
- patch 是空的時，ref 指向 `base`。寫入失敗時，`update` 刪除這個 ref，並記錄錯誤。
- `Shadow` 在一個佇列中依序執行所有 git 指令。
- `check_merge { a, b }` 執行 `git merge-tree --write-tree --name-only refs/oceania/<a> refs/oceania/<b>`。exit code 1 時，回傳衝突的檔案。
- Produces（`src/shadow.ts`）：
  - `class Shadow`，建構子是 `constructor(dir, url = cloneUrl)`。測試用 `url` 傳入本機的 bare repo。
  - `cloneUrl(repo)`：把 `github.com/o/r` 轉成 `https://github.com/o/r.git`。
  - `update(session, git: { repo, base, patch }): Promise<void>`：回傳的 Promise 不會 reject。
  - `merge(a, b): Promise<MergeResult>`：`status` 是 `missing`、`clean` 或 `conflict`。`conflict` 另外有 `files`。
- `SYSTEM_PROMPT` 加入一條規則：兩個 session 的 diff 修改同一個檔案時，呼叫 `check_merge`。
- 測試：`check_merge reports a same-line conflict` 與 `check_merge passes changes in different files`。

### Task 10：每 60 秒重新同步，並偵測停滯的 session

- `startMaster` 每 `resyncMs` 執行確定性檢查。預設值是 `RESYNC_MS`，也就是 60 秒。
- 狀態是 `working`，而且 `STALL_MS`（10 分鐘）沒有事件的 session：Oceania 加入一次 `stall` 事件，文字是 `<who> may be stalled.`。這個 task 把 `stall` 加入 `EventKind`。
- 確定性檢查呼叫 `memory.reportStalls(Date.now() - STALL_MS)`。
- `Memory.reportStalls(before): void`：`working` 的 session 最後的事件不晚於 `before` 時，`reportStalls` 加入 `stall` 事件。
- `stall` 事件一直是這個 session 最後的事件，直到這個 session 加入新的事件。因此 Oceania 對每次停滯只回報一次。
- `stall` 事件不觸發判斷回合。
- 測試：`resync reports a stalled session once`。

### Task 11：`run_in_worktree`

- `run_in_worktree { a, b }` 先合併兩個 session 的 shadow ref。
- 合併沒有衝突時，Oceania 用 `git worktree add` 在暫存資料夾建立合併後的 worktree，再執行 `npm test`。Oceania 一定刪除這個 worktree。
- `npm test` 最多執行 `TEST_TIMEOUT_MS`，也就是 `ROUND_MS` 的一半。逾時時，Oceania 停止整個 process group。
- 測試的環境變數不包含 `.env` 的 token 與 API key。
- 這個工具回傳失敗的輸出，最多 `MAX_TEXT`。
- Produces（`src/shadow.ts`）：`test(a, b): Promise<TestResult>`。`status` 是 `missing`、`conflict`、`untested`、`passed`、`failed` 或 `timeout`。
- `untested` 表示 `package.json` 沒有 `test` script。
- `SYSTEM_PROMPT` 加入一條規則：一個 diff 修改另一個 diff 使用的程式碼時，呼叫 `run_in_worktree`。
- 測試：`run_in_worktree returns test failures`。

spec §10 的 P1 項目「在 `Stop` 檢查 diff 是否偏離」已經包含在 P0 中，不需要另一個 task。原因如下：
  - 每個 `diff` 事件都觸發判斷回合。
  - `Stop` 先等待 `settled()`，再結束這一輪。因此 master agent 在 agent 閒置前檢查最後的 diff。
